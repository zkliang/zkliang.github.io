用 GitHub Pages 搭一个自己的网址导航：零成本，30 分钟上线

2026-08-05 · 约 9 分钟阅读

收藏夹塞了 200 个链接、浏览器书签栏挤到换行、团队要共享一份「常用工具清单」却只能用在线文档贴——这是不是你的日常？我后来想通了：与其和浏览器书签较劲，不如自己搭一个「网址导航页」：一个干净网页，左边是分类，右边是链接，手机电脑都能开。

最省事的方案，是用 GitHub Pages：它把你的静态网页免费托管在 xxx.github.io，不用买服务器、不用管运维。下面我把从「零」到「上线」的每一步讲清楚，全程零成本。

一、为什么选 GitHub Pages，而不是买服务器

普通网址导航站本质就是「一个静态网页 + 一堆链接」，不需要后端、不需要数据库。这种需求用 GitHub Pages 最划算：

· 免费：静态站点托管目前完全免费，流量大也不收费；
· 稳：背后是 GitHub 的全球 CDN，比自己租的小服务器靠谱；
· 可绑定自己的域名：想要 nav.你的名字.com 这种专属地址，几十块钱买个域名就行；
· 自带版本管理：每次改链接都是一次提交，改错了随时回退。

如果你只是想「把链接收拢到一个页面」，这几乎是成本最低、最不怕丢的方案。我在 FreeNav 之前也这么折腾过，最后才做成现在这个带搜索、能收藏的完整版——但你从简版起步，完全够用。

二、30 分钟上线的四步

第 1 步：建一个仓库

注册 GitHub 账号（免费），新建一个仓库，名字取 你的用户名.github.io。这个特殊命名会让 GitHub 自动把它当成你的个人站点。仓库选「Public」即可。

第 2 步：放一个 index.html

在仓库里新建 index.html，写一个简单的导航页：用 <ul> 列分类、每个分类下用 <a> 放链接。不用会框架，纯 HTML 就够。想要好看一点，可以套一个免费的静态模板（搜「startpage」「homarr 风格」能找到不少）。

第 3 步：开启 Pages

进仓库的 Settings → Pages，Source 选「Deploy from a branch」，分支选 main、目录选 /root，保存。等一两分钟，浏览器打开 https://你的用户名.github.io 就能看到了。

第 4 步（可选）：绑定自己的域名

想甩掉 .github.io 尾巴，去域名商（比如阿里云）买个简短的域名，然后在 Pages 里填进去、并按提示加一条 CNAME 解析。几十块钱一年，专有感立刻上来。

三、想省事？直接用现成的导航模板

不想从空白 HTML 写起，可以用社区维护的开源导航项目：它们大多一键部署、自带搜索和分类，你只填链接就行。FreeNav 本身也是这类思路的进化版——如果你想要「分类更细、带软件介绍、还能收藏」的体验，直接逛逛 FreeNav 的工具清单当灵感，或者参考我们的开源替代专题挑一组你真正常用的工具先放上去。

四、几个小提醒

· 别把私密链接放公网：GitHub Pages 是公开的，放公司内网地址、个人云盘这类就别公开了；
· 链接失效要勤理：导航页最大的敌人是「点开 404」，每季度扫一遍；
· 想要更高阶的「自托管面板」（能登录、能多人协作），可以看我们另一篇自建网址导航方案对比，里面有零代码到自托管的完整路径。

写在最后

网址导航不是什么高科技，但它能实实在在省下你每天「找链接」的时间。GitHub Pages 这条路线，零成本、不怕丢、还能绑自己的域名——对大多数人来说，已经是甜点区。
