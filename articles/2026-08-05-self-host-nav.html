想自己搭个开源网址导航？从 0 到上线，我用过的方案

2026-08-05 · 约 9 分钟阅读

先说清楚「网址导航」是什么：它和你浏览器里的收藏夹一样，是把常用网站摆在一个页面上、点一下就跳。区别是——收藏夹只有你自己看，网址导航可以是一个网页，能分享、能团队共用、能当新标签页。

我自己的 FreeNav 最初就是这么来的：收藏夹塞了 200 多个链接，找东西比搜还慢。于是我把它搬成了一个网页。下面把走过、试过的 4 条路讲清楚，从零代码到自托管，你按自己的技术胃口选。

一、先想清楚：你要的是哪种「导航」

需求不同，方案天差地别：

· 个人清爽起始页：只要自己打开浏览器第一眼看到常用站，别无广告；
· 团队 / 家庭共享：多人维护一份书签，比如家人共用影视 / 工具入口；
· 对外发布的资源站：像 FreeNav 这样，给陌生人看、还能 SEO 被搜到；
· 纯折腾乐趣：有自己的服务器，想玩自托管面板。

对号入座后再往下看，能省很多时间。

二、方案 1：零代码静态站（GitHub Pages）

这是 FreeNav 自己用的路子，也最适合「想自己掌控、又不想学后端」的人。

做法：写一份 HTML（其实就是把链接分类排好），扔到 GitHub 仓库，开启 Pages，它就变成一个公开网址。零服务器、零费用、不怕跑路——GitHub 替你托管。

优点：完全可控、不追踪用户、内容想写什么写什么、还能被百度 / 谷歌收录带来自然流量。
缺点：要会一点 HTML；想要评论、登录这类动态功能得另接服务。

适合：想做一个「长期资产型」导航站、甚至 future 想靠流量变现的人。这篇专栏里我反复强调的，就是这种「属于自己的、不被平台拿捏」的站点。

三、方案 2：开箱即用的起始页服务

如果你连 HTML 都不想碰，start.me 这类服务最省事：注册后拖拽添加书签、分栏分组，还能跨设备同步、生成公开页分享给别人。

优点：五分钟上手，无需技术；
缺点：数据在别人服务器上、免费版功能受限、品牌是别人的。适合「只想用、不想拥有」的人。

四、方案 3：自托管面板（有服务器 / NAS 的人）

如果你家里有 NAS、或者有台轻量云服务器，可以跑 Heimdall、Homarr、Dashy 这类开源导航面板。它们专为「自托管全家桶」设计：Docker 一键起，界面漂亮，能显示服务状态（比如「我家 Plex 在线吗」）。

优点：功能强、可玩性高、数据完全在自己手里；
缺点：要会装 Docker、要维护服务器。这是「爱好级」方案，不是给小白的。

五、方案 4：浏览器书签 + 同步（最朴素）

说句大实话：很多人需要的只是「换设备也能看同一份书签」。那 Chrome / Edge 的同步功能就够了，配合「书签栏分组」，比任何导航站都轻。

适合：需求极简、不想额外维护任何东西的人。它解决不了「分享给别人」和「被搜索到」。

六、本站的实际做法（给你一条最小路径）

FreeNav 走的是方案 1：一份纯静态 HTML + 一点 CSS/JS，托管在 阿里云的轻量服务器上（新用户通常有首单优惠，服务器是建站绕不开的基础投入）。之所以没用 GitHub Pages 而用独立服务器，是因为后续要接统计、广告、自定义域名更灵活——但对只想搭个个人导航的新手，GitHub Pages FREE 就够。

最小路径就三步：

① 在 GitHub 建个仓库，写一份带分类链接的 index.html；
② 仓库设置里开启 Pages；
③ 想要自己的域名，再去买一个、按提示解析。完事。

想看实战细节，可以读我们的新人装机清单，里面也涉及「工具怎么组织才不乱」的思路，和搭导航是一回事。

写在最后

搭网址导航本身不难，难的是「坚持维护」。所以我的建议是：从最小可用开始——先放 20 个你真常用的链接，跑通上线，再慢慢加。别一上来就追求完美分类，那会劝退自己。

如果你也想做一个「不被平台拿捏、长期属于自己的」导航 / 资源站，FreeNav 就是个现成范本：开源、静态、可白嫖托管。也欢迎在 GitHub 上交流你的玩法——我也在持续迭代它。
